# v1.1.0 代码审计说明

## 审计范围

本次按 GitHub 正式发布标准检查：

- Windows UI Designer（Go / Win32）
- ESP32-S3 固件（Arduino/C++）
- ANT / JK / JBD / 彦阳协议解析
- BMSUI v1–v7 parser/runtime
- SPIFFS 主题事务存储
- Web 配置与 UI 上传
- 主机测试、示例、发布脚本和文档

## 本次整理

### 代码逻辑

- 将 Designer 当前 Theme Version `110` 和 Layout Schema `8` 集中为单一常量，删除多处重复硬编码。
- 将 Designer `v1.1.0` 应用版本集中为 `appVersion`，标题栏和侧栏统一引用。
- 修复“新建空白画布”仍写入旧 Schema 6 的遗留值，统一使用当前 Schema 8。
- 保留原有 BLE、Web、协议、动态 UI 和主题事务逻辑，避免为了形式上的重构破坏已验证链路。

### 注释

- 普通业务代码只保留必要的极简英文注释。
- `//go:build`、`//go:embed` 等编译指令保留。
- 详细参数解释集中在 `firmware/src/app_config.h`、`firmware/lv_conf.h` 和 `docs/固件配置与部署.md`。

### 文档

- 删除开发阶段 Hotfix/临时修复说明。
- 合并 PSRAM、图片资源、矢量资源、单位锚点等重复文档。
- 统一当前设备协议为 **BMSUI v7**。
- 重写 README、CHANGELOG、升级说明、部署说明、协议说明、Release 说明和发布清单。

## 保留的核心模块

以下均由当前功能链路实际使用，不属于冗余：

- 四类 BMS 协议解析
- BLE 扫描、连接、订阅和自动恢复
- 统一 BMS 数据存储
- Factory UI
- BMSUI v1–v7 parser/runtime
- SPIFFS 自定义主题事务存储
- Web 配置、主题上传/下载/恢复 API
- 动态 UI 启动保护
- 屏幕电源管理和按键逻辑

## 静态检查与主机测试

执行：

```bash
bash tools/run_host_tests.sh
```

覆盖：

- ANT / JK / JBD / 彦阳协议测试
- 仪表盘状态和测试模式逻辑
- 显示休眠逻辑
- BMSUI parser 与 CRC/资源解析
- UI 数据绑定
- v2–v7 示例主题校验
- Designer 源码特征检查
- 发布源码审计
- Win64 Go 交叉编译

额外执行：

```text
gofmt: PASS
python py_compile: PASS
go vet: 2 个 Win32 unsafe.Pointer 边界提示
```

`go vet` 的两处提示分别位于 Win32 `WM_DRAWITEM` 消息结构转换和 DIB 像素缓冲映射。它们是 Win32 ABI 互操作所需的指针转换，Win64 构建和功能测试均通过，因此没有为了消除提示而改写底层调用。

## 本次没有盲目修改的区域

- BLE 状态机
- Web AP / 登录 / UI 上传协议
- BMS 协议帧解析
- SPIFFS 事务提交
- LVGL 动态 UI 资源生命周期

这些模块已经有较强状态依赖，且当前基线测试通过。没有证据表明存在缺陷时，大规模“重构”会提高硬件回归风险，不符合“不影响运行和功能”的要求。

## 实机验证边界

当前环境没有 Arduino CLI/目标板工具链，因此主机侧无法替代最终 ESP32-S3 完整编译和实机回归。发布前仍应在真实目标板完成 `docs/发布检查清单.md` 中的硬件项目。

## 结论

v1.1.0 已完成发布层面的代码收敛、版本口径统一、低风险冗余消除、文档重构和主机回归。剩余发布风险主要来自目标 Arduino 环境和真实 BLE/显示硬件组合，应通过最后一次实机验证关闭。
