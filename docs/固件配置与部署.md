# 固件配置与部署

## 1. 目标硬件

- MCU：ESP32-S3
- 显示：ST7789，320×240 横屏
- BMS：ANT / JK / JBD / 彦阳 YY
- UI 存储：SPIFFS
- 外部 RAM：可使用 PSRAM；动态 UI 按运行时实际可用容量判断，不绑定某个固定 8 MB/16 MB 型号

## 2. 接线

| 功能 | GPIO | 说明 |
|---|---:|---|
| TFT CS | 10 | SPI 片选 |
| TFT RST | 9 | 屏幕复位 |
| TFT DC | 8 | 数据/命令 |
| TFT MOSI | 11 | SPI 写数据 |
| TFT SCLK | 12 | SPI 时钟 |
| TFT MISO | 13 | SPI 读数据 |
| TFT 背光 | 7 | PWM 背光控制 |
| 用户按键 | 6 | 低电平有效 |

权威定义以 `firmware/src/app_config.h` 为准。

## 3. Arduino 环境

打开：

```text
firmware/ANT_BMS_Arduino_IDE.ino
```

工程代码按以下主版本 API 编写：

- Arduino-ESP32 3.x
- NimBLE-Arduino 2.x
- LVGL 8.4.x
- LovyanGFX：选择与当前 Arduino-ESP32 兼容的稳定版本

`lv_conf.h` 必须使用仓库提供的版本。`partitions.csv` 必须与 `.ino` 位于同一 Arduino sketch 目录。

主循环栈设置为 20480 bytes，用于覆盖 Web 配置和主题上传调用路径。

## 4. app_config.h 配置说明

`firmware/src/app_config.h` 是固件运行参数的唯一集中配置入口。普通业务代码不应重复硬编码这些值。

### Firmware

定义固件名称、版本号和开发者信息。GitHub Release 改版本时应优先修改这里，并同步 Designer 的 `appVersion`。

### Pins

定义屏幕和用户按键 GPIO。只有实际接线变化时才修改。

### Display

包含：

- 屏幕宽高、方向和颜色顺序。
- LVGL 刷新缓冲行数。
- SPI 读写频率。
- ST7789 复位/休眠/唤醒延时。
- 背光 PWM 频率和分辨率。

如果出现颜色反转、红蓝互换或方向不对，应优先检查 `RgbOrderBgr`、`InvertColors`、`SwapColorBytes`、`Rotation`，不要在 UI 层做补偿。

### DisplayPower

自动调暗/休眠参数。应用层已统一电流方向：**充电为正，放电为负**。该区阈值直接影响车辆活动判断，不建议在不了解算法的情况下同时改多个阈值。

### Button

按键低电平有效，默认：

- 消抖 35 ms。
- 1 秒内三击切换屏幕开关。
- 长按 10 秒进入配置/UI 热点流程。

### Ble

包含四类 BMS 的名称识别规则、服务/特征 UUID、扫描/重连/握手时序、连接参数以及通知缓冲区大小。不同 BMS 适配问题应优先在对应 `src/protocol/` 和 BLE 服务中定位，不建议通过无依据放大超时值解决。

### Range

里程估算参数：保留容量、默认 km/Ah 系数和允许范围。km/Ah 可在 Web 页面修改。

### WebConfig

包含 SoftAP、HTTP、启动重试、UI 提交时序和默认管理密码。

默认：

```text
SSID：无用脑洞研究所
IP：192.168.4.1
密码：123456
```

首次部署后建议修改默认密码。当前 Web 配置只用于设备本机管理，不应暴露到公网。

### Protocol

限制最大帧长、电芯/温度数量及电压、电流、功率等合理范围，用于拦截异常或损坏的数据帧。修改这些上限前应确认真实 BMS 协议范围。

### Runtime

顶层启动、主循环 yield、重启和恢复连接延时。通常无需修改。

## 5. 分区与主题文件

`partitions.csv` 预留 SPIFFS 用于自定义 UI。运行时主要文件：

```text
/ui.bmsui   当前主题
/ui.tmp     上传暂存
/ui.bak     更新备份
/ui.bad     被拒绝主题
```

主题提交使用事务流程：暂存 → 解析校验 → 备份 → 正式写入 → SPIFFS 重挂载验证 → 清理事务文件。

## 6. PSRAM 与内存策略

v1.1.0 不再根据开发板商品型号硬编码 12 MiB/16 MiB 门槛。只要 ESP32 heap capability 实际提供足够可用 PSRAM，动态 UI 即可继续构建。

- LVGL 对象、样式和临时绘制：PSRAM 优先。
- 图片、A8 蒙版、动态字体图集：PSRAM 优先。
- GLYPHVAL 每控件输出 mask：PSRAM 优先。
- LCD/DMA 和需要内部 capability 的缓冲：保留内部 RAM。
- 无 PSRAM 时使用较低运行时资源预算；检测到可用 PSRAM 后自动提高预算。

启动日志和 `/api/ui/info` 可用于检查 PSRAM 总量、空闲量、最大连续块和当前动态 UI 资源上限。

## 7. 第一次升级 v1.1.0

从 v1.0.0 升级时必须通过 USB 烧录一次 v1.1.0，因为设备端需要 BMSUI v7 parser/runtime。之后只改主题时不需要重复刷固件。

## 8. 配置热点与 UI 下发

1. 正常运行时长按用户按键 10 秒。
2. 设备重启并进入配置/UI 热点。
3. Windows 连接热点。
4. Designer 中输入 `192.168.4.1` 和管理密码。
5. 点击“检测设备”。
6. 点击“发送 UI”。
7. Designer 等待上传、校验、提交完成。
8. 设备重启并加载 `/ui.bmsui`。

“恢复原始 UI”只删除自定义主题，Factory UI 编译在固件中，始终保留。

## 9. 发布前实机回归

至少验证：

- Arduino 完整编译和烧录。
- Factory UI 正常启动。
- 实际使用的 BMS BLE 连接和实时数据。
- Web 登录、保护板扫描、配置保存。
- 读取 UI、发送 UI、恢复原始 UI。
- PNG、动态字体、渐变、双状态图片和进度控件。
- 8 MB/16 MB PSRAM 目标硬件上的启动和内存日志（按实际硬件选择）。
- 自动调暗、休眠、三击和长按按键。
